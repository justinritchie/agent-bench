Method

  • priority = 0.45*public_norm + 0.25*own_success + 0.15*speed_rank + 0.15*cost_rank: weights public 0.45, own success 0.25, speed 0.15, cost 0.15; every input is 0–1.
  • Public: each class metric is min-max scaled across the engine/model pairs ranked here, then averaged; 0.5 when a model has none.
  • Harness discount: a score measured in another agent's harness counts at 0.8× (marked ×0.8), for example a Terminal-Bench run in Claude Code credited to Antigravity running the same model. The engine's own harness, or a model-only benchmark, counts in full.
  • Own success: quality of own jobs from a weekly random sample of jobs graded against their own instructions (pass 1, partial 0.5, fail 0) once a pair has enough graded jobs; until then the share of own jobs in the last 28 days that finished cleanly, or 0.5 with fewer than 10 jobs. Speed: rank by own median minutes, else Artificial Analysis output speed, else 0.5.
  • Cost: weight 0.15; the cheaper choice scores higher when quality is close. Cost per successful job comes from own jobs (3 or more in the class), else the model's list price times the engine's typical job size, else 0.5; it is ranked on a log scale, cheapest 1. The $ to $$$$ tier is the model's list price alone (3 input : 1 output tokens, four log-spaced bins).
  • Evidence first: Proven means at least 5 own jobs in the last 28 days. Scores within 0.03 tie (marked tie) and go to more own jobs, then lower cost, then speed. An unproven entry ranks above a proven one only on a clear public margin: more than 0.03 ahead and a higher public score (else marked evidence), never on cost or speed alone. Quality before cost: an unproven entry leads only with a public score within 0.05 of the best.
  • Effort: the label next to a model is the reasoning effort to run it at: the standing default (Claude Code Fable medium, others high; Codex and Grok their config; Antigravity the -high id), moved only when a public leaderboard scores another level at least 0.03 higher for that class.
  • Kinds of work: Coding and agentic subclasses are ranked the same way, on the public metrics that measure that kind of work and own jobs of that kind; a subclass with neither is not listed.
  • Only aggregate job counts, success rates and median minutes are published; no prompts, job details or grades. Model lists for Grok CLI are unverified.

Terminal-Bench 4.0
  • Each task gives an agent an instruction and its own environment; the agent works in the terminal, and a verifier's tests decide whether the task was done.
  • Scored as accuracy over trials, with at least 5 trials per task; errored trials count as failures, and an LLM judge reviews successful trials for reward hacking.
  • A submission is one agent harness, model and reasoning effort together, so a score says as much about the harness as the model; we count a score from another agent's harness at 0.8x.
SWE-bench Verified
  • A model, inside an agent scaffold, gets a GitHub issue and its repository and has to produce a patch that fixes it.
  • Scored as the percentage of tasks resolved, out of 500 SWE-bench tasks that human annotators checked for clear problem statements and correct tests.
  • The standard test for fixing bugs in existing code. Caveat: entries are a model plus a scaffold, and the board had no recent entries for most models we rank.
SWE-bench Multilingual
  • SWE-bench-style tasks in other languages: 300 tasks from 42 repositories in C, C++, Go, Java, JavaScript, TypeScript, PHP, Ruby and Rust.
  • A task counts as resolved when the patch passes two sets of unit tests taken from the original pull request.
  • Would tell us about repo work outside Python. Caveat: none of the models we rank has an entry yet, so it affects no ranking today.
Artificial Analysis coding index
  • A single coding score per model that Artificial Analysis publishes in its API, from its own runs of coding evaluations.
  • Its methodology page does not list which evaluations make up this index, so we do not describe its parts.
  • Not in use: the API needs a key we do not use, so no model has a value here.
Arena Text: coding
  • People ask a question in Arena's battle mode, see answers from two anonymous models side by side and vote for the better one; this board keeps only prompts Arena classifies as coding.
  • Ratings come from a Bradley-Terry fit to those votes, published as the Arena score.
  • Shows whose coding answers people prefer in chat. Caveat: preference in a chat answer, not whether the code runs in a repository.
Arena WebDev
  • Code Arena: two anonymous models build a web app or page from the same request and people vote on the result; Arena describes it as full-stack web development with multi-step reasoning, tool use and end-to-end app generation.
  • Rated from the votes and published as the Arena score; one model can appear at two reasoning efforts.
  • Our best signal for frontend and UI work. Caveat: it judges the finished app as people see it, not the code behind it.
Artificial Analysis agentic index
  • A single agentic score per model that Artificial Analysis publishes in its API.
  • Its methodology page does not list which evaluations make up this index, so we do not describe its parts.
  • Not in use: the API needs a key we do not use, so no model has a value here.
Arena Agent: bash reliability
  • A shell-command signal from Agent Arena, which analyses real sessions of people using Agent Mode on arena.ai for their own work.
  • Published as an IPS score with a 95% confidence interval; Arena's methodology post does not define this particular signal, so we do not describe how it is counted.
  • Feeds terminal and sysadmin work. Caveat: the sessions run in Arena's own agent, on whatever tasks its users bring.
Arena Agent: bash recovery
  • After a shell command errors in a real Agent Mode session, how many more turns the agent takes to reach a command that runs; giving up is penalised.
  • Published as an IPS score with a 95% confidence interval.
  • Feeds terminal and sysadmin work. Caveat: measured in Arena's own agent, on its users' tasks.
Arena Agent: tool calls
  • In real Agent Mode sessions, a task is marked a failure when the agent calls a tool that does not exist.
  • Published as an IPS score with a 95% confidence interval; the spread between models is small.
  • Feeds tool and connector workflows. Caveat: it catches invented tools, not wrong arguments to real ones.
Arena Agent: task outcome
  • At the end of a real Agent Mode session the user marks the task a success or a failure in Arena's interface.
  • Published as an IPS score with a 95% confidence interval.
  • Feeds tool and connector workflows. Caveat: each user judges their own task, in Arena's agent.
DeepResearch Bench
  • 100 PhD-level research tasks (50 in Chinese, 50 in English) across 22 fields, written by domain experts; a system writes a full research report for each.
  • Reports are judged by RACE, which compares them with reference reports using an LLM judge, and FACT, which checks how many citations are effective and accurate; we read the leaderboard's total score.
  • Would tell us about deep research. Caveat: most entries are research products, not the models we rank, and none of ours has an entry.
Arena Search
  • Arena's leaderboard for searching the web: people compare two anonymous models' answers side by side and vote.
  • Rated with a Bradley-Terry fit to the votes, published as the Arena score.
  • Feeds research. Caveat: few of the models we rank have an entry.
Arena Document
  • People upload a PDF, ask about it, and compare two anonymous models' answers side by side.
  • Rated with a Bradley-Terry fit to the votes, published as the Arena score.
  • Feeds reading. Caveat: questions about one uploaded document, not reading across many files.
Arena Text: creative writing
  • Arena Text battles in the creative writing category: two anonymous answers, and people vote for the one they prefer.
  • Rated with a Bradley-Terry fit to the votes, published as the Arena score.
  • Feeds writing. Caveat: taste in short chat answers; it says nothing about long documents or a house style.
Arena Text
  • All Arena Text battles: people see answers from two anonymous models side by side and vote for the better one.
  • Rated with a Bradley-Terry fit to the votes, published as the Arena score; we use the raw ratings, not the style-controlled ones.
  • Feeds writing as a general quality signal. Caveat: a broad mix of everyday prompts, specific to no one task.
Artificial Analysis output speed
  • How fast a model streams its answer: tokens received per second after the first token, measured on the same endpoint Artificial Analysis uses for price.
  • Higher is faster; we would scale it across the models we rank.
  • Only a fallback when we have no timings of our own. Not in use: the API needs a key we do not use.
OpenRouter prices
  • The per-token prices OpenRouter lists for each model, taken from the top provider for that model, in US dollars.
  • We blend 3 input tokens to 1 output token and show dollars per million tokens; lower is cheaper.
  • Sets the $ to $$$$ tier, and the cost estimate when we have fewer than 3 priced jobs of our own. Caveat: one provider's list price, which can differ from the model maker's own price.
Own jobs
  • The jobs we hand to these agents in our own work, counted per engine and model for each task class and kind.
  • Own success is the share that finished cleanly or, once a pair has enough graded jobs, the mean grade from a weekly random sample graded against each job's own instructions; median minutes and list-price cost also count.
  • Only aggregate counts and rates are published, never the jobs themselves. Caveat: our own task mix, not a general benchmark.
